01 · Problem area and why

Stop uncertainty before it becomes a system record

EV-charger submissions can arrive late, incomplete, inconsistent, and in several formats through contractors and integrators.

The intake reality

  • CSV and spreadsheets
  • JSON and third-party APIs
  • Semi-structured text

Why this slice

  • One defensible checkpoint before downstream reporting
  • Preserve source lineage and explicit unknowns
  • Escalate uncertainty instead of inventing completeness

We do not claim access to Con Edison internal data, measured labor savings, or regulatory compliance.

02 · Background research

Heterogeneity is part of the official data ecosystem

Surprising fact

DOE AFDC combines daily network APIs, periodic spreadsheet/CSV imports, and manual records in one national charging-station directory.

Design implication: The design target should not be a complete-looking row. It should be an inspectable row with values, unknowns, conflicts, and source mappings.

Sources: DOE Alternative Fuels Data Center; NREL developer documentation; Con Edison PowerReady; NYSDPS Case 18-E-0138.

VoltStream · synthetic/public data onlyBackground research and surprising fact · 3/13

02 · 背景研究

异构性本就是官方数据生态的一部分

意外发现

DOE AFDC 的全国充电站目录同时汇集每日网络 API、定期电子表格/CSV 导入以及人工维护记录。

设计含义： 设计目标不应是生成一行看似完整的数据，而应是生成一行可检查的数据，其中数值、未知项、冲突和来源映射都清晰可见。

来源：美国能源部 Alternative Fuels Data Center、NREL 开发者文档、Con Edison PowerReady、NYSDPS Case 18-E-0138。

07 · Recommendation to Con Edison

Continue learning—without granting automation authority

Limited, offline, fully human-reviewed pilot using guarded Codex as the current reference.

Operating guardrails

  • Use approved data only and retain the original payload
  • Keep field-level provenance with every proposal
  • Require human review; forbid authoritative writes
  • Zero tolerance for unsupported critical values or unsafe under-routing

Before expansion

  1. Raw-source ambiguity rule
  2. Deterministic text-lineage extraction
  3. Larger blind, independently labeled test set

07 · 给 Con Edison 的建议

继续学习，但不要授予自动化权限

开展一个有限、离线、全程人工复核的试点，以 guarded Codex 作为当前参考路线。

运行护栏

  • 只使用获批数据，并保留原始载荷
  • 每个建议值都保留字段级来源
  • 强制人工复核，禁止写入权威系统
  • 对关键字段无依据补全和不安全路由实行零容忍

扩大范围之前

  1. 加入原始来源歧义规则
  2. 加入确定性文本来源提取
  3. 使用更大的盲测集并进行独立标注

08 · What could go wrong

One run on ten synthetic cases is not production evidence

Model driftProvider versions and behavior can change.
Automation biasPlausible structure can still hide false lineage.
Format driftNew contractor inputs and multi-row files remain untested.
PrivacyProduction data handling has not been reviewed.
Operational costLatency, reviewer load, and scale economics are unknown.
Schema limitsEight fields cannot represent every business distinction.

Next gate: repeated runs, dual human labels, privacy review, reviewer-workload evidence, and explicit rollback criteria.

The evidence supports learning safely—not automating yet.

08 · 潜在风险

10 个合成案例的一次运行并不是生产证据

模型漂移供应商版本和模型行为可能变化。
自动化偏误结构看似合理，来源追踪仍可能错误。
格式漂移新的承包商输入和多行文件尚未测试。
隐私生产数据处理方式尚未经过审查。
运营成本延迟、复核工作量和规模经济仍未知。
Schema 边界8 个字段无法表达所有业务差异。

下一道门槛：重复运行、双人标注、隐私审查、复核工作量证据和明确回滚标准。

证据支持我们安全地继续学习，而不是现在就自动化。

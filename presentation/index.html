Con Edison EV charger data · Capstone project

When two files disagree about a charging site, should AI choose?

Con Edison is a company that delivers electricity. Outside companies send it files about vehicle-charging locations—called charging sites—but those files do not always agree.

We built and tested an AI assistant: software that reads the varied files, organizes the facts, checks for problems, and knows when a person must decide.

01 · The business problem

Messy files turn data entry into a judgment call

A contractor may send a spreadsheet, a record from another software system, or a written note. The same charging site can be described differently—or have important information missing.

What arrives

  • Different column names and file formats
  • The same charging power written as 7,200 watts or 7.2 kilowatts
  • Missing or conflicting numbers

What an employee must decide

  • Which value can be trusted?
  • Where did that value come from?
  • Can the new entry continue, or must someone review it?

Our project focuses only on this first check. We did not use Con Edison internal data or claim measured labor savings.

02 · What we learned from research

Even national databases combine mismatched sources

What we found

The U.S. Department of Energy's charging-station directory combines daily files from charging networks, uploaded spreadsheets, and entries edited by staff.

What this means: A useful system must show what it knows, what it does not know, and which place in the original file supports each answer. A fully filled-in result is not enough.

03 · What our test version actually does

Four steps turn an incoming file into a review decision

1

Read

Open a spreadsheet, software record, or written note

2

Organize

Place the same 8 facts into consistent positions

3

Check

Find missing, invalid, or conflicting values

4

Decide

Continue (ACCEPT) · ask a person (HUMAN_REVIEW) · stop (REJECT)

AI suggests values; fixed checking rules written by our team make the final decision.

The 8 facts are a site ID (unique label), address, charging-speed category, port count, power, connector type, operating status, and the original entry's ID.

04 · What failed and what we changed

Our first AI approach chose a number when it should have stopped

The first broad AI cleaner saw two different port counts, chose 8, and allowed the entry to continue. We stopped using that approach as the default.

The invalid run was a testing-process problem, not an AI failure. Our evidence uses only the later run whose cases, rules, and files could no longer be changed after it started.

File-reading failureOne example contained a software record inside another record. The first reader failed, so we repaired it and added a repeat test.
Model-setting failureOne AI service did not support a requested output setting. We simplified the setting and tested the replacement.
Invalid test runThe runner reported completion before all result files finished saving. We corrected the process and excluded that run.

04 · The case that changed our decision

One site reported 8 installed ports but only 6 active

Both numbers can be true. The output table provides only one general port-count column and does not say which meaning it expects. Codex and DeepSeek are two kinds of AI systems compared in this project.

installed_ports means all physical ports installed8

active_ports means ports active now6

Safe response: leave it blank and send it to a person (saved as null + HUMAN_REVIEW)

Choosing 8 treats all installed ports as if they were working now; choosing 6 treats currently active ports as the full installed total. 07 · Our recommendation

Use it as an assistant—not as the decision-maker

The evidence supports only a small trial—a pilot—of Codex with safety rules, with a person checking every result. It is not ready for live company use.

Rules for the trial

  • Use only approved test data and keep the original file
  • Show exactly where every suggested value came from
  • Do not let the tool update an official system
  • Stop the trial after any invented important number or unsafe continuation

Before considering wider use

  1. Add a rule that separates installed ports from currently active ports
  2. Point every answer from a written note back to its exact sentence
  3. Have independent reviewers write correct answers for a larger test set

07 · 我们的最终建议

把它当作助手，而不是最终决策者

现有证据只支持一个小规模试验（pilot）：使用带安全规则的 Codex，并由人检查每一个结果。它还不能进入公司的真实业务使用。

试点必须遵守的规则

  • 只使用获批的测试数据，并保留原文件
  • 每个建议数值都必须显示来自原文件的哪里
  • 不允许工具更新任何正式系统
  • 出现一次重要数字编造或不安全继续，就停止试验

考虑扩大使用之前

  1. 增加区分已安装端口与当前启用端口的规则
  2. 让文字说明中的每个答案指回准确原句
  3. 由独立复核人员为更大测试集写出正确答案
